\chapter{OpenROAD Project and Installation}

\section{OpenROAD Overview}

OpenROAD is an open-source RTL-to-GDSII digital physical design flow developed under the DARPA OpenROAD project. It provides an automated backend implementation flow starting from synthesized RTL and ending with a manufacturable GDSII layout.

The OpenROAD ecosystem consists of multiple open-source tools integrated into a unified backend flow. Major components used during this internship include:

\begin{itemize}
    \item \textbf{Yosys} --- RTL synthesis tool
    \item \textbf{OpenROAD} --- Physical design engine
    \item \textbf{OpenSTA} --- Static timing analysis
    \item \textbf{TritonRoute} --- Detailed routing engine
    \item \textbf{KLayout} --- GDSII layout viewer
\end{itemize}

The backend implementation flow used during this project was based on the \textbf{sky130hd} standard cell library provided by the SkyWater 130\,nm open-source PDK.

\section{OpenROAD Flow Scripts (ORFS)}

OpenROAD Flow Scripts (ORFS) provide an automated Makefile-based backend implementation flow for RTL-to-GDSII design generation.

The complete flow includes the following stages:

\begin{enumerate}
    \item \textbf{Synthesis} --- Verilog RTL is synthesized into a gate-level netlist using Yosys.
    
    \item \textbf{Floorplanning} --- Core area and die area are generated for physical implementation.
    
    \item \textbf{Placement} --- Standard cells are placed inside the core region.
    
    \item \textbf{Clock Tree Synthesis (CTS)} --- Clock distribution buffers are inserted.
    
    \item \textbf{Routing} --- Global routing and detailed routing are performed.
    
    \item \textbf{GDSII Generation} --- Final layout is exported as a \texttt{.gds} file.
\end{enumerate}

The ORFS infrastructure was used as the primary backend flow engine during the OpenROAD integration with eSim.

\section{OpenROAD Installation}

OpenROAD Flow Scripts were installed by cloning the official repository and executing the provided setup scripts.

\begin{lstlisting}[language=bash, caption={OpenROAD Flow Scripts installation commands.}]
$ git clone --recursive \
https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts

$ cd OpenROAD-flow-scripts

$ sudo ./setup.sh

$ ./build_openroad.sh --local
\end{lstlisting}

The installation process downloads required dependencies, builds OpenROAD from source, and installs the required backend tools locally inside the ORFS directory.

After compilation, the OpenROAD executable becomes available at:

\begin{lstlisting}[language=bash]
OpenROAD-flow-scripts/tools/install/OpenROAD/bin/openroad
\end{lstlisting}

\section{Yosys and KLayout Setup}

Yosys was installed as part of the OpenROAD Flow Scripts build process. KLayout was installed separately for GDSII layout visualization and inspection.

\begin{lstlisting}[language=bash, caption={KLayout installation command.}]
$ sudo apt install -y klayout
\end{lstlisting}

The generated layout files were verified using both OpenROAD GUI and KLayout during backend testing.

\section{Environment Variables and Path Configuration}

The backend integration module \texttt{OpenROAD.py} was configured to automatically locate the OpenROAD and Yosys binaries inside the ORFS installation directory.

The following configuration paths were used:

\begin{lstlisting}[language=python, caption={Tool path configuration inside OpenROAD.py.}]
ORFS_PATH = "/home/rj/eSim/OpenROAD-flow-scripts"

OPENROAD_BIN = ORFS_PATH + \
"/tools/install/OpenROAD/bin/openroad"

YOSYS_BIN = ORFS_PATH + \
"/tools/install/yosys/bin/yosys"
\end{lstlisting}

These paths were configured directly inside the backend module to avoid manual environment variable configuration during execution.

\section{ORFS Directory Structure}

The OpenROAD Flow Scripts infrastructure follows a structured design hierarchy for storing flow configuration files and generated backend outputs.

\begin{lstlisting}[language=bash, caption={ORFS design directory structure.}]
OpenROAD-flow-scripts/
`-- flow/
    |-- designs/
    |   `-- sky130hd/
    |       |-- FullAdder/
    |       |   |-- config.mk
    |       |   `-- constraint.sdc
    |       |
    |       `-- HalfAdder/
    |           |-- config.mk
    |           `-- constraint.sdc
    |
    `-- results/
        `-- sky130hd/
            |-- FullAdder/
            |   |-- 6_final.gds
            |   |-- 6_final.def
            |   `-- ...
            |
            `-- HalfAdder/
                `-- ...
\end{lstlisting}

The \texttt{designs/} directory stores configuration and constraint files, while the \texttt{results/} directory stores generated backend outputs such as DEF and GDSII layouts.
